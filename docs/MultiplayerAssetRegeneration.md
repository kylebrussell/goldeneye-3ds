# Reproducible incremental multiplayer pack regeneration

`scripts/regenerate_3ds_multiplayer_pack.py` rebuilds the 74 canonical character
dependencies and all 11 multiplayer arenas from a verified US ROM, then replaces
their complete prefixes in an existing fullpack. Every other payload is preserved
byte-for-byte. The receipt records their inherited hashes; it does **not** establish
their original converter provenance or claim a fresh conversion of the fullpack.

This procedure needs no copied `build/u/assets`, extracted images, split assets,
Docker build, texture converter, emulator, or SD card. The source checkout must
contain the multiplayer converter/registry from `b961a797` and the 74-character
dependency staging change from `e3c5c2da`, or equivalent current source. The
runtime game and its registry still need their own build and gameplay validation.

## Run from canonical local inputs

Use an actual Python 3.10+ interpreter and absolute, symlink-free paths. On macOS,
`/tmp` and `/var` are symlinks; use their real `/private/...` locations if needed.
Run the helper from the checkout containing this tooling. Set these four paths
to existing inputs and a new, task-local evidence directory:

```sh
source_checkout=/absolute/path/to/canonical/source-checkout
source_rom=/absolute/path/to/ge007.u.z64
base_fullpack=/absolute/path/to/original/goldeneye.u.gepack
evidence=/absolute/path/to/new-asset-regeneration-evidence
mkdir -p "$evidence"

python3 scripts/regenerate_3ds_multiplayer_pack.py lock \
  --source-root "$source_checkout" \
  --rom "$source_rom" \
  --base-pack "$base_fullpack" \
  --output "$evidence/lock.json"

python3 scripts/regenerate_3ds_multiplayer_pack.py build \
  --lock "$evidence/lock.json" --output "$evidence/first"
python3 scripts/regenerate_3ds_multiplayer_pack.py build \
  --lock "$evidence/lock.json" --output "$evidence/repeat"

python3 - "$evidence" <<'PY'
import hashlib, json, pathlib, sys
root = pathlib.Path(sys.argv[1])
receipts = [json.loads((root / name / 'receipt.json').read_text())
            for name in ('first', 'repeat')]
for name, receipt in zip(('first', 'repeat'), receipts):
    assert receipt['status'] == 'complete'
    pack = root / name / 'goldeneye.u.gepack'
    assert hashlib.sha256(pack.read_bytes()).hexdigest() == receipt['pack_update']['output']['sha256']
    assert all(command['exit_status'] == 0 for command in receipt['commands'])
assert receipts[0]['lock_sha256'] == receipts[1]['lock_sha256']
assert receipts[0]['pack_update']['output']['sha256'] == receipts[1]['pack_update']['output']['sha256']
assert receipts[0]['pack_update']['output']['entries'] == receipts[1]['pack_update']['output']['entries']
assert receipts[0]['canonical_payload_inventory_sha256'] == receipts[1]['canonical_payload_inventory_sha256']
print('Both runs produced', receipts[0]['pack_update']['output']['sha256'])
PY
```

The lock refuses any ROM other than US SHA-1
`abe01e4aeb033b6c0836819f549c791b26cfde83`, checks the pack's ROM lineage,
and also binds the actual ROM and fullpack with SHA-256. It inventories all Python
sources under `scripts/`, the ROM file list, canonical setup/STAN source, model
metadata, character/stage tables and expected registry. The source commit and
working-tree status are recorded; exact source-file hashes are authoritative,
including when the checkout has uncommitted changes.

`build` rechecks the lock and captures those exact sources and ROM into its new
output directory. It extracts character payloads directly from the ROM and runs
the character stager, its independent `--check` invocation, and the multiplayer
converter with `--check` against the captured registry. The latter validates
source intro/spawn/STAN geometry against ROM data while converting collision,
rooms and bounds. The wrapper additionally checks staged character bytes and
arena backgrounds/setups against its own canonical ROM payload inventory.
Shared setup files and regional `setup/u` files are resolved by unique canonical
stem, rejecting missing or ambiguous matches.
Validation uses an immutable capture of all generated bytes. Before accepting
the receipt, the wrapper compares its complete validated entry inventory with
the actual regenerated entries in the new pack, rejecting changes made after
validation.

The captured Python interpreter runs with `-I -S -B`, a fixed environment and only
the captured scripts explicitly added to the import search path. The lock binds
the real executable bytes, Python/platform/zlib versions, relevant standard
library module bytes and both update helper files. It records the actual Python
conversion runtime, not a Docker image label for commands that did not run. This
is local repeatability evidence, not a hermetic operating-system image: system
libraries and the entire OS are not vendored. Recreate the lock after changing
the interpreter, helper, canonical source, base pack or ROM.

## Evidence and preservation

Each successful output directory contains:

- `lock.json`, the exact input contract used by the run.
- `canonical-source/` and `source-rom.z64`, the private captured inputs.
- `canonical-payloads.json`, with compressed ROM offsets/lengths/hashes and
  expanded size/SHA-256 for every relevant character/background/setup/STAN entry.
- `generated/`, containing the fresh characters and all multiplayer arenas.
- `logs/`, containing actual combined stdout/stderr for all three converter
  invocations. The receipt binds each command, working directory, exit status,
  log size and SHA-256. Absolute output paths can make repeat log hashes differ.
- `goldeneye.u.gepack` and `receipt.json`, containing the final fullpack and
  complete before/after entry inventories, hashes, sizes, replacement prefixes,
  preserved names, regenerated names and removed names.

Only `converted/models/characters/` and `converted/multiplayer/` are replaced.
Replacing a prefix removes obsolete entries inside it; similarly named siblings
are preserved. The strict version-1 pack reader checks header/index bounds,
canonical ordering and padding, path hashes, duplicate names and FNV collisions.
The updater rejects traversal, symlinks in input/output ancestors or replacement
trees, nonregular inputs, overlapping prefixes and existing output files. It
compares every inherited payload before creating the new pack atomically.
The pack format has no stored payload checksums; the receipt supplies SHA-256
inventories and input binding, not retrospective authenticity for inherited data.

Inputs are read-only. The output directory must be new; prior evidence is never
replaced. An interrupted or failed run retains `failure.json` and available logs
and removes an unreceipted candidate pack when Python handles the failure.
A process kill or power loss can prevent cleanup, so accept only a successful
receipt whose pack hash verifies. Keep all generated ROM/assets/evidence private;
do not commit or redistribute them with the public tooling.

## Tool validation

The tests use synthetic payloads and need no ROM:

```sh
python3 -m unittest \
  scripts.tests.test_gepack_update \
  scripts.tests.test_verify_3ds_asset_pack \
  scripts.tests.test_multiplayer_pack_regeneration
```

They check byte-exact compatibility with the existing packer, repeatability,
inherited payload preservation, stale-prefix removal, malformed/colliding input,
unsafe paths and symlinks, concurrent output creation, file mutation, source and
runtime lock changes, decompression bounds, actual isolated converter execution,
failed conversion, interruption immediately after pack publication, and payload
mutation between validation and packing. All 38 tests pass.
