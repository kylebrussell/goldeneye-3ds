# Native multiplayer fog provider

The character and object render gates now have their original native fog
owner: `ge_original_multiplayer_fog_slice.c`, generated by
`scripts/extract_multiplayer_fog_slice.py`. It owns the unchanged US fog tables,
current environment, near-fog reference, coefficients, selected/main/alternate
records and original load, switch, distance-colour and culling functions.
`chrobjFogVisRangeRelated` is extracted from `propobj.c`; the US near-fog struct
tag is aliased to the floating-point type expected by that original body.

## Startup and teardown

Before native players exist, call
`ge_original_stage_environment_select_for_player_count(level, cinematic, count, out)`
for the renderer's preview environment and clipping range. Selection follows
`fogLoadLevelEnvironment`: cinematic `level+900`, stage `level+100*count`
(count one uses offset zero), multiplayer default `100*count`, then the
fogless stage/default. The existing `select` entrypoint remains count one.

After native player creation and before world constructors or visibility
queries, call `ge_original_multiplayer_fog_load(level, cinematic, count, scale)`.
Count must match native `getPlayerCount`. Scale is the stage's original
visibility scale, not its room geometry scale. The extracted fog loader uses
this service instead of the camera adapter's not-yet-populated scale. Native
`viSetZRange` remains the original VI/perspective service, including its native
current-player camera-scale side effects. Subsequent shooter camera publication
must use the same selected clipping range.

Call `ge_original_multiplayer_fog_close` during unified stage teardown, before
native player/VI dependencies disappear. It clears stage-owned references and
restores source initial values without invoking VI. Repeated close is safe.
An in-stage reload/alternate transition retains original behavior: in
particular, an original fogless load does not clear an existing near-fog
pointer. A fresh stage load after close begins with null references.

## Build ownership

Compile both new adapter and generated slice with the normal native US type
flags. Use `-DGE_PORT_NATIVE_FOG` for the combined native build, including
scheduler-support and AI-support objects. Their old fog globals and bodies
are guarded by that macro; isolated legacy fixtures can keep their previous
ownership without linking the new provider. Native VI, player-count,
`getPlayer_c_lodscalez`, camera-matrix and player-position services are external
dependencies. This change does not edit main or the 3DS Makefile.

The native render entrypoints keep the original signatures from `bgfog.h`
and `propobj.h`: `fogGetPropDistColor` returns 0/1/2 for fully obscured,
fog-coloured, or unmodified; `chrobjFogVisRangeRelated` uses native zDepth,
model size and the currently selected player's LOD scale. Both are read-only.
The original zero-depth division and untouched output on disabled/behind-camera
paths are preserved. No synthetic distance or local renderer state replaces
these inputs. Actual renderer integration remains root/body ownership.

## Validation and coverage limit

`scripts/test_multiplayer_fog.sh` passes native and short-enum ASan/UBSan.
It compares 256 native/pure selections (all 21 solo and 11 multiplayer
descriptors, player counts 1–4, cinematic off/on), including all sky/water
values and native fog ranges. Separate assertions cover the authored Bunker
count overrides, count defaults, cinematic precedence, colour culling/fade
regions, near-fog thresholds, model-size/LOD changes, world-position culling,
read-only queries, alternate transition, invalid startup and teardown.
The unchanged solo environment hash remains `b623c46258a8a414`.
Both new native translation units compile with actual devkitARM.

The public snapshot is a diagnostic value copy, not a complete multiplayer
state exporter or coverage attestation. Mutable native fog fields, including
the alternate environment's static record, need typed state coverage before
any complete digest claim. There is no hardware, timing or visual acceptance
claim in these host checks.
